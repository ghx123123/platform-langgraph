## 1. 目标与背景

把"资料单元"工作台（教师准备：选课次、匹配大纲要求、组织知识大纲、AI 生成教学补充）与"课程设计"工作台（教师基于已有大纲打磨教学方案 + 多智能体生成与导出）真正打通，让教师从资料单元整理出的成果（重难点、教学补充、大纲节点）**直接进入课程设计**作为可组装素材，而不再只是孤立记录。

核心挑战：
1. 资料单元有解析后的**教材正文 + 教学大纲 + 教学补充**，但课程设计之前只能拿到标题清单。
2. 资料单元的大纲是**多版本 + 可编辑**的，课程设计必须钉住某版快照（教案交付物），同时支持大纲升级时显式重绑。
3. **不重复解析**：课程设计不能再对已解析的教材做第二次 OCR/版面分析。

## 2. 设计与决策

### 2.1 引用语义 = 快照 + 升级徽标

- 课程设计记录增加 `material_unit_id + knowledge_outline_id + knowledge_outline_version` 三字段，定向钉住大纲某版本。
- 前端调用 `import-design` 时**强制传** `knowledge_outline_version`（不再"省略=最新"的隐式路径）。
- 新增 `GET /course-designs/{id}` 返回 `outline_has_newer_version / outline_latest_version`；新增 `POST /course-designs/{id}/rebind` 显式升级（version+1，保留 `_versions` 历史，解除旧版 409 锁）。
- 升级是**显式用户意图**，教案是交付物不能默默漂移。

### 2.2 不重复解析 = 导入前 precheck + 后台解析补齐

- 新增 `POST /api/material-units/{id}/import-precheck`：报告每份材料的 `parse_status`，未完整提取的标 `needs_parse`。
- 前端按 precheck 结果触发 `POST /parse-tasks`（并发 2），用并行进度条展示每份解析进度。
- 全部 `parsed` 后才真正 `createRun`，杜绝进入课程设计后"二次解析"。

### 2.3 教学补充/证据落进课程设计

- `CourseDesignKnowledgeNode` 扩展字段：`description / teacher_note / evidence`。
- `_resolve_knowledge_outline` 整节点保留进 `source_snapshot.knowledge_nodes`（不再剥字段）。
- `assembly_sources` 新增 `outline:{id}:note` 来源：把资料单元生成的 AI 教学补充作为可插入块（默认 `target=postscript`）进入内容编排。

### 2.4 默认选材 = 知识范围已选教材

- 教师在资料单元"确定教材知识范围"里勾选的章节（`selectedTextbook`）反查 `textbook_outline` 的 `source_material_id` → 映射回档案中的 `material_ids`，作为导入默认选中（不默认全选）。
- 无选中时回退到第一本教材。导入按钮统一收敛到大纲列顶部（删除底部冗余按钮）。

### 2.5 dsh agent 化（B 方案）

把内容分析+教学设计合并为一个真正**自主迭代、带多轮记忆**的 dsh agent 会话；讲授/提问/答疑/督导保留 LangGraph（本就是独立 prompt）。

- **桥协议 v0.3.2**：`agent_run` 方法用同一 `session_id` 做 N 轮自主迭代（每轮基于上一轮 final_response 修订），复用 session 让 dsh 多轮记忆。
- **真实验证**：用 python 第 1 章真实教材（11132 字 + 大纲 v5）做 A/B 对比：单次 9 个散点 vs 2 轮 11 个成体系知识点（含【概述】/【应用】/【版本演进】式前缀）。核心价值是**结构化主线 + 自查补全**。

## 3. 关键 bug 排查与根治（生成过程可见性）

症状：从资料单元导入课程设计后，前端一直停在"正在建立第一份分析结果"空态，看不到任何节点进度。最终定位是**三段串联故障**：

### 3.1 uvicorn Win+reload 强 Selector loop → dsh 桥 NotImplementedError（最隐蔽）

**根因**：`uvicorn/loops/asyncio.py::asyncio_setup(use_subprocess=True)` 在 win+reload 模式下强制 `WindowsSelectorEventLoopPolicy`，而 `asyncio.create_subprocess_exec` 只在 Proactor loop 上支持 → dsh 桥 spawn 失败 → run 卡在 content_analysis。

**铁证**：
| 启动方式 | 跑通率 | NotImplementedError 计数 |
|---|---|---|
| `uvicorn ... --reload` (默认开发) | 0/3 | 2 |
| `uvicorn ...` (无 reload) | 2/2 | 0 |

**根治**：给 dsh 引擎配**常驻独立 Proactor loop（后台线程）**，桥子进程的 spawn / stdout 读取 / 请求收发全部跑在它上面，与主 app loop 类型解耦。实现见 `backend/workflows/dsh_engine.py::_ensure_loop_thread / _run_on_loop / _ensure_started_internal / _generate_internal / _agent_run_internal`。**关键技巧**：跨 loop future 用 `asyncio.wrap_future` 而非直接 `await`，否则抛 "attached to a different loop"。

### 3.2 前端 selectRun 闪一下消失

**根因**：`App.tsx:490` 的 `useEffect`：`if (activeDesign && !activeDesign.run_id && selectedRunId) setSelectedRunId(null)`——所有 design 的 `run_id` 默认是 None，历史 run 全部被立即清理。

**修复**：新增 `userSelectedRunRef`，`selectRun` 时置位，effect 仅在"非用户主动选择"时清理。

### 3.3 content_analysis JSON 提取偶发失败

**根因**：minimax 末轮输出偶尔带说明+代码块，`_balanced_object` 第一个 `{` 配平对象 `json.loads` 失败即抛 → 兜底 `analysis={}` → 下游空 dict 让 run failed。

**修复**：提取失败时自动 `generate_json` 重试，日志打末轮原始输出前 300 字便于诊断。

## 5. 系统架构（本节变动部分）

### 5.1 后端新端点
| 端点 | 作用 |
|---|---|
| `POST /api/material-units/{id}/import-precheck` | 报告每份材料的解析状态，标记 `needs_parse` |
| `POST /api/course-designs/{id}/rebind` | 升级课程设计到资料单元大纲最新版 |
| `POST /api/workflows/...` (桥协议) | 新增 `agent_run` 方法（同一 session 多轮自主迭代） |

### 5.2 关键模型变化
- `CourseDesignKnowledgeNode` 扩字段：`description / teacher_note / evidence`
- `CourseDesignRecord` 增字段：`outline_has_newer_version: bool, outline_latest_version: int | None`
- `MaterialUnitImportPrecheckResponse` 新模型
- `DshAgentEngine` 新方法：`agent_run` / 常驻 Proactor loop

### 5.3 前端 UX 改进
- **导入前解析进度对话框**：并行进度条，逐份显示"未解析/解析中/完成"
- **课程设计列表显示大纲版本徽标**：📌 "已更新至 vN" + "一键升级"按钮
- **材料预览默认进提取文本模式**：不再展示原始 PDF，直接看解析后的正文
- **生成过程日志面板**：从 events 流解析实时进度（节点 + 心跳 + 完成时间线）
- **导入按钮统一到顶部**：删除底部冗余入口
- **左列可拖拽调宽**：知识大纲 + 内容目录列支持 220-480px 拖动
