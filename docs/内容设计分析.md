# 如何设计更利于教师和学生的内容 —— 基于《Python 程序设计基础与应用》第 2 章实测

> 依据：用真实课本 PDF 走通"解析 → 剖析 → 设计 → 讲授 → 分层提问 → 答疑 → 督导 → 成果"全流程，
> 对比修复前后 mock 产出、真实模型（MiniMax-M3）产出与督导评价，提炼对教师/学生两类用户的内容设计原则。

## 一、两类用户的内容需求

| 用户 | 核心诉求 | 平台应产出 |
|------|----------|------------|
| 教师 | 拿来就能上课、能改、能导出 | 教学目标（可测量）、教学环节（含时长）、**可当堂讲授的讲授稿**、**课堂练习与答案**、分层问题、易错点清单、督导改进建议、教案导出（PDF/MD） |
| 学生 | 听得懂、练得会、能自检 | 生活化/代码化导入、概念讲解 + **可运行代码示例**、**分层练习（基础/进阶/拓展）**、常见误区提醒、即时反馈 |

## 二、实测证据与设计要点

### 1. 内容必须"钉"在课本上（锚定）
- **实测问题**：修复前 content_analysis 重点为 OCR 噪声（"推荐用法/创建字典对象"），讲授稿与上传文档无关。
- **修复**：把解析出的候选知识点作为"权威锚点"传给每一阶段模型。
- **实测效果（真实模型）**：内容剖析精确覆盖"内置对象分类 / 强类型动态语言 / 数字类型 / 容器对象 / 运算符多重含义 / 内置函数清单 / 海象运算符 / 无 ++--"；讲授稿围绕"三种数字类型"展开并带代码示例。
- **原则**：解析环节的质量（OCR 纠错、知识点清洗）直接决定教学产出质量，是第一优先级。

### 2. 讲授稿要"可口头执行"
- **实测发现（督导点评）**："框架规划了学生完成 3 道填空题，但实际只有一道带 <details> 的思考题，且 <details> 标签在课堂口头讲授中无法触发"。
- **修复**：讲授 prompt 明确"不要使用网页标签/Markdown 表格；需含 2 个课堂小练习，先停顿口答、再公布答案"。
- **原则**：生成物要面向"教师对着学生讲"的真实场景，而不是网页阅读场景。

### 3. 认知冲突 > 平铺直叙（学生可理解性）
- **实测亮点（真实模型）**：用 `8.4 - 0.1 == 8.3` 的"反直觉"结果制造认知冲突，再给 `math.isclose()` 标准方案；用 `2024 + '2024'` 报错现场演示强类型。
- **原则**：编程内容应多用"错误示范法 + 反直觉现象 + 可验证示例"，让学生先"踩坑"再理解原理。

### 4. 分层不是贴标签，而是差异化深度
- **实测亮点**：基础层讲清 j/i 工程惯例；进阶层深入 CPython 浮点存储机制；拓展层对比 IEEE 754 vs Decimal/Fraction 并点出 `Decimal(0.1) vs Decimal('0.1')` 陷阱。
- **原则**：三层问题/回答必须是同一知识点的三个深度，而不是三个无关问题。

### 5. 督导点评要"可执行、可迭代"
- **实测亮点**：下一轮重点具体到 `-7//2=-4`（向下取整）、`-7%3=2`（余数符号）、`2**3**2=512`（右结合），并给出 5 分钟上机热身任务。
- **原则**：改进建议必须可操作（含具体例子/练习），下一轮讲授才会真正变化，而非重复轮次。

### 6. 练习与评估是内容闭环的最后一块
- **现状**：课堂练习融入讲授稿（"停顿口答 + 公布答案"），分层提问覆盖即时评估，报告含形成性评价方案。
- **后续建议**：可扩展为结构化的"课堂练习库（level + 题目 + 答案）"与"课后作业"，并接入课本"本章习题"锚点。

### 7. 交互体验支撑长任务
- **实测**：真实模型 1 轮约 141 秒、2 轮约 5 分钟；前端已具备阶段进度条、轮次/时长胶囊、"谁在做什么"提示、随时停止。
- **本次改进**：启动前新增耗时预期提示（本地演示模型约 10 秒 / 真实模型 1 轮约 2-3 分钟）。
- **原则**：长时任务必须给用户"进度可解释、时长可预期、操作可中止"三重安心。

## 三、给后续迭代的设计清单
1. 结构化"课堂练习/课后作业"产出（对接课本习题锚点）。
2. 讲授稿自动附"可复制到 IDE 的代码块"（前端 Markdown 已支持 ``` 代码块）。
3. 教案导出增加"教师用版（含答案与追问）/ 学生用版（仅练习）"。
4. 督导建议按"问题-示例-改法"三段式约束，保证可执行。
5. 前端在运行中提供"预计剩余时长"（按已用时长 × 已完成节点比例估算）。
