# 开源项目赋能评估（2026-08-12）

## 1. 结论

当前平台已经形成完整且边界清晰的教师备课主链：

```text
课程资料库（建立索引、原文预览）
→ 资料单元（按需提取、进度表/大纲/教材对齐、知识大纲）
→ 课程设计（教师/学生/督导围绕同一知识范围迭代）
→ 成果中心（可编辑 DOCX、原页 PDF 预览、版本与来源记录）
```

下一阶段不需要再引入一套“知识库平台”或更换多智能体框架。开源项目能带来真实收益的地方主要有三项：

1. **证据化结构抽取**：用强类型 schema 和原文定位提高不同模板进度表、教学大纲的识别稳定性。
2. **质量回归与运行追踪**：让“多轮后是否更好”从主观感觉变成可重复验证的指标。
3. **按质量路由的文档解析**：只让低质量扫描页、复杂表格页和公式页进入增强解析，保留当前快速主链。

建议优先顺序：

```text
P0  Instructor 风格的 Pydantic 强类型输出 + Promptfoo 固定样本回归
P0  LangExtract 原文定位隔离实验
P1  PaddleOCR PP-StructureV3 低质量页面路由实验
P1  Phoenix 开发环境追踪，或 Langfuse 团队化部署（二选一）
P2  SQLite FTS5 全文索引
P2  docxtpl/docxcompose 仅补充复杂模板和成果组合能力
Reject  整体接入 RAGFlow、LlamaIndex UI、GraphRAG、Paperless-ngx 或替换 LangGraph
```

## 2. 当前能力与真实缺口

| 环节 | 当前已有能力 | 仍需解决的问题 |
|---|---|---|
| 资料库 | 本地路径层级、文件指纹、刷新差异、延迟提取、原文件打开 | 当前搜索是内存子串匹配，大规模跨学期资料检索能力有限 |
| 文档提取 | PyMuPDF + RapidOCR v6；DOCX/PPTX/XLSX 结构读取；逐页质量报告 | 不同模板的大纲和进度表语义字段仍依赖规则；复杂表格、公式和混合版面需增强 |
| 资料单元 | 进度表讲次、教学大纲、教材标题层级；来源 hash、locator、evidence | 首次结构化抽取缺少严格 schema 重试和原文可视化核验 |
| 知识大纲 | 教师确认范围、版本记录、证据约束、细化范围锁定 | 需要固定样本持续计算章节越界率、证据覆盖率和重点召回率 |
| 课程设计 | LangGraph 检查点、生成状态、token/耗时、三智能体迭代 | 缺少跨模型、跨提示词、跨版本的可重复效果对比 |
| 成果中心 | DOCX 模板预检、原格式填充、PDF 预览、导出血缘与 SHA-256 | 复杂循环区域、多文档合并、附件组合仍可加强，但不是当前首要瓶颈 |

现有关键接口已经足够承载增强能力，不宜另起一套数据模型：

- 文档质量路由：`backend/documents/service.py::_quality_report`、`parse_document`
- 资料库延迟提取：`backend/course_archives/service.py::_parse_uploaded`
- 范围选择与证据：`backend/material_units/service.py::build_scope_options`、`refinement_evidence`
- 模型结构输出：`backend/workflows/llm.py::ModelClient.generate_json`
- 知识大纲细化：`backend/material_units/router.py::_model_refined_nodes`
- 模板预检与导出：`backend/course_designs/service.py::inspect_docx_template`、`build_docx`
- 当前资料检索：`backend/data_hub/service.py::filter_catalog`

## 4. 推荐架构

### 4.1 文档解析：快速主链 + 质量门 + 增强适配器

保留当前主链：

```text
PDF: PyMuPDF native text → 页面质量判断 → RapidOCR v6（扫描页）
DOCX: python-docx + OOXML 文本框/表格/标题
PPTX: python-pptx + Office 原页预览
XLSX: openpyxl/xlrd 结构化单元格
```

在 `_quality_report` 后增加统一路由协议，而不是把某个开源项目写死：

```python
class DocumentEnhancer(Protocol):
    def supports(self, extension: str, report: dict) -> bool: ...
    def extract(self, source: bytes) -> EnhancedDocument: ...
```

仅在以下条件触发 PP-StructureV3/Docling 对照：

- `quality_level == "low"`
- 表格页原生提取为空或列错位
- 公式/图表密集且教师选择“增强识别”
- 标题层级缺失，且该文件被指定为教材或教学大纲

增强结果必须保留：`engine/version/page/bbox/confidence/source_hash`，不得覆盖原始提取结果。教师应能在“原提取 / 增强提取 / 原页”之间切换后确认采用版本。

### 4.2 资料单元：强类型抽取 + 原文落点

为不同文档角色定义稳定 schema：

- `TeachingSchedule`: 讲次、周次、学时、教学内容、实验/理论、来源单元格
- `SyllabusRequirement`: 课程目标、知识要求、重点、难点、实践、考核、来源区间
- `TextbookHeading`: 标题、层级、页码、父节点、来源区间
- `ScopeAlignment`: 选中讲次、匹配大纲要求、教材候选范围、匹配分数、证据

推荐分工：

- `Instructor/Pydantic` 负责 schema 校验、缺字段重试和类型稳定。
- `LangExtract` 只负责长文本字段抽取和原文字符区间定位。
- 当前 `refinement_evidence` 继续作为后端最终安全边界；模型不能自行扩大教材范围。

教师核验界面应显示三列而不是一段分析：

```text
识别字段 | 识别值 | 原文证据（页码/单元格/高亮片段）
```

只有被教师确认的结构记录才进入 `build_scope_options`。这样“智能识别”与“教师决定范围”的责任不会混在一起。

### 4.3 多智能体：不换 LangGraph，增加可测量的 evaluator-optimizer

当前课程设计已经使用 LangGraph 检查点，不建议迁移 AutoGen、CrewAI 或 MetaGPT。更有效的增强是为每轮生成保存统一评分：

```text
scope_leakage_rate       章节越界率
evidence_coverage        有原始/结构证据的知识点比例
required_point_recall    教学重点召回率
supervisor_action_rate   督导建议被下一版落实的比例
template_field_coverage  导出模板字段填充率
latency_ms / input_tokens / output_tokens
```

督导输出继续保持“优点 / 不足 / 建议”，但每条建议增加 `target_section` 和 `acceptance_rule`。下一轮不是继续讲新内容，而是对同一 `knowledge_outline_id + version + allowed_node_ids` 做修改，然后由确定性规则先检查范围，再由模型评估质量。

### 4.4 运行评估：Promptfoo 先行，观测平台后置

先在仓库中建立脱敏的固定样本集和 CLI 回归，不急于部署观测平台：

```text
tests/fixtures/evaluation/
  schedule-3-templates/
  syllabus-3-templates/
  textbook-native-pdf/
  textbook-scanned-pdf/
  textbook-mixed-pdf/
  ppt-text-and-diagram/
  lesson-plan-template/
```

Promptfoo 负责批量运行模型和提示词组合；Python 断言负责硬指标。等指标稳定后，再选择 Phoenix 或 Langfuse 之一记录运行 trace。不要同时部署两个观测平台。

## 5. 实验与质量门

### 实验 A：大纲/进度表证据化抽取（P0）

对照组：当前规则 + `generate_json`。

实验组：Pydantic 强类型重试；LangExtract 原文落点作为可选增强。

至少使用 3 种进度表、3 种大纲模板，不得只测一个标准文件。通过门槛：

| 指标 | 目标 |
|---|---:|
| 讲次行召回率 | ≥ 95% |
| 教学内容字段准确率 | ≥ 95% |
| 重点/难点召回率 | ≥ 90% |
| 可定位到原文的字段比例 | ≥ 95% |
| 无证据字段进入知识大纲 | 0 |
| 相对当前耗时增加 | ≤ 50%，或由用户明确选择增强模式 |

### 实验 B：低质量页面增强解析（P1）

对同一批 PDF 页分别运行当前主链、PP-StructureV3、Docling；MinerU 只选公式/复杂版面页参加对照。

| 指标 | 说明 |
|---|---|
| 页面覆盖率 | 有效正文页面 / 总页面 |
| 标题层级 F1 | 一级、二级、三级标题及父子关系 |
| 表格单元格准确率 | 单元格文本、行列位置、合并关系 |
| 公式与图注召回率 | 仅对人工标注页计算 |
| 误增内容率 | 不存在于原页的文本比例 |
| CPU 总耗时、峰值内存、模型下载量 | 必须在当前 Windows 环境记录 |

新引擎只有在目标文档类型上至少提升 10 个百分点，且耗时可被“增强识别”交互解释时，才进入正式依赖。

### 实验 C：教学设计迭代质量回归（P0）

固定同一个知识大纲和教材范围，运行两轮教学设计。必须同时满足：

- 章节越界率为 0。
- 所有新增知识点有证据且属于允许父节点。
- 第二轮落实至少 80% 可执行督导建议。
- 不因切换页面、超时或重启丢失任务状态。
- 失败重试不会生成重复版本。
- 每轮记录模型、提示词版本、输入/输出 token、耗时和错误类型。

### 实验 D：Word 成果组合（P2）

只在出现“循环表格、动态图片、多份附件合并”的真实模板时，对照当前引擎、docxtpl 和 docxcompose。比较：

- 页面数、节、纸张、页边距是否变化。
- 表格数、合并单元格、行高列宽是否变化。
- 页眉页脚、编号、样式和字体是否变化。
- 模板字段覆盖率和残留占位符数量。

当前已通过真实模板的导出链不应因引入通用模板库而回退。

## 6. 数据与安全前置条件

本地检查发现运行目录内存在明文 API Key 配置和用户导入源码中的密钥文本。相关目录当前已被 `.gitignore` 排除，未发现被 Git 跟踪，但在接入 trace、数据集或第三方评估前仍必须完成：

1. 轮换当前模型密钥，避免历史本机副本继续有效。
2. `ModelSettings` 改为系统凭据存储或环境变量引用，JSON 仅保留 key id/是否配置。
3. 对导入源码做 secret scanning；命中密钥模式时，原文仍可本地保存，但不得进入模型提示词、trace 或评估数据集。
4. trace 默认仅记录 hash、文档 id、页码、节点 id、token 和耗时；正文片段需要显式开启且先脱敏。
5. 所有固定回归样本使用脱敏副本，不把教师原始材料提交到公共仓库。

这是部署 Phoenix/Langfuse 之前的硬门槛。

## 7. 分阶段落地建议

### 第一阶段：先建立质量基线（3–5 个开发日）

- 建立脱敏固定样本和人工金标准。
- 为现有解析、范围对齐、知识大纲和 DOCX 导出增加统一评分脚本。
- 用 Promptfoo 对比当前模型、提示词和结构 schema。
- 为 `ModelClient.generate_json` 增加 Pydantic 模型校验接口；先在资料单元使用。

验收物：一条命令输出每项指标及与基线的差异，失败时阻止合并。

### 第二阶段：证据化抽取（5–8 个开发日）

- 建立 `StructuredExtractionProvider`，当前实现与 LangExtract 实现并存。
- 只对“进度表/大纲分析”启用，不触碰课程设计范围锁定。
- 增加原文证据核验视图和教师确认状态。
- 保存 extractor、版本、模型、prompt version、source hash 和字符/单元格定位。

验收物：三类不同模板全部达到实验 A 门槛，切换页面后核验状态不丢失。

### 第三阶段：解析增强与可观测性（5–10 个开发日）

- PP-StructureV3 作为独立 worker/进程，只处理低质量页。
- Docling 保留为对照，不默认安装到主环境。
- 在脱敏完成后，优先开发环境接 Phoenix；需要多人提示词协作时再评估 Langfuse。
- 数据规模增长后先启用 SQLite FTS5，达不到中文检索目标再评估 Meilisearch。

验收物：增强引擎在目标样本上有量化提升，关闭增强服务时当前主链仍可完整运行。

## 8. 最终取舍

最值得做的不是“接入更多 AI 项目”，而是建立下面这条受控增强链：

```text
原文件与 hash
→ 快速解析
→ 质量报告
→ 必要时增强解析
→ 强类型字段
→ 原文证据定位
→ 教师确认
→ 范围锁定
→ 多智能体迭代
→ 固定指标回归
→ 可追溯 Word 成果
```

这条链能直接改善教师体验：识别结果可核验、等待过程可解释、知识范围不会漂移、不同模型效果可以比较、历史结果可以复用。相比整体引入热门知识库或多智能体框架，它与当前平台的业务边界更一致，风险和重复功能也更少。
