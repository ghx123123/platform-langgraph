# 介入功能优化方案（决策 3）+ 其余决策落地

> 2026-09-08 · 需求来源：用户要求「把用户输入作为真实反馈进入多智能体课堂」
> 关联：`docs/课程设计功能优化方案_2026-09-08.md`（第一轮 A/B/C/D 已落地）

---

## 0. 现状诊断（实测，非推测）

介入链路**已存在一半**，但用户输入在三个环节被截断：

| 环节 | 现状 | 证据 |
|---|---|---|
| 输入 | ✅ 课堂演练聊天框，active/paused 均可输入 | `ClassroomGroupChat.tsx:204` |
| 持久化 | ✅ 存为 `classroom.user.intervention` | `orchestrator.py:481-490` |
| 教师回应 | ✅ 口头回应一句 | `orchestrator.py:493-508` |
| **后续行为** | ❌ **被明令禁止影响课堂** | `orchestrator.py:502`：「直接回应…**不切换 Slide，不修改 Lesson Blueprint**」 |
| **督导评价** | ❌ 无「教师指令是否被遵守」维度 | `evaluation.py:77-85` 的 schema 无此字段 |
| **落到课件** | ❌ 不进 `RevisionPatch` | `revision.py:40-79` 只吃 `report + observations` |
| **两个勾选框** | ❌ classroom_v2 完全不读 | `graph.py:339/425` 是 legacy `teaching_v1` 的；`backend/classroom/*` 零引用 |

**结论**：用户说了话，课堂听见了，但没记住、没照做、没落到课件。三个勾选项里的两个是「骗人控件」。

---

## 1. 目标

用户输入成为一等公民：**说一次，全程生效，且能落到课件里可追溯**。

```
教师输入「这个例子太难，换成生活化的」
  ↓ 意图=纠正 / 范围=本轮剩余
  ├─ 后续每次 teacher.act / students.act 都带上这条指令（约束继承）
  ├─ 督导评价新增「指令遵循度」维度；未遵循 → alignment observation
  └─ 生成 RevisionPatch 改到下一版课件；复盘页可溯源
```

## 2. 设计

### 2.1 数据模型

**新增 `TeacherDirective`**（`backend/classroom/models.py`）

| 字段 | 类型 | 说明 |
|---|---|---|
| directive_id | str | uuid |
| run_id / round_id | str | 归属 |
| slide_id | str? | 发出时所在页 |
| source_event_id | str | 关联的 USER_INTERVENTION 事件 |
| content | str | 教师原话 |
| intent | Literal["question","correct","require"] | 提问/纠正/要求 |
| scope | Literal["slide","round","lesson"] | 本页/本轮剩余/整节课 |
| status | Literal["active","resolved","superseded"] | 生效中/已落实/被覆盖 |
| created_at / resolved_at | datetime | |

**存储**：新建表 `teacher_directives`（migration `006_teacher_directives.sql`），与现有 `classroom_events` 同级。

**为什么不塞进 ClassroomState**：state 是「当前游标」，指令是「历史累积且跨轮生效」，语义不同；且 lesson 范围要跨 round 存活。

### 2.2 约束继承（让输入持续生效）

`ClassroomOrchestrator` 持有 `runtime.active_directives`，在三个调用点注入：

| 调用点 | 注入内容 |
|---|---|
| `teacher.act`（讲授/答疑/反馈） | `prompt_context["teacher_directives"]`：生效中的指令列表 |
| `students.act`（学生提问/回答） | 同上（教师要求「多提问」时学生要感知） |
| `evaluator.evaluate_slide` | 同上 + schema 新增 `directive_compliance` |

**指令生命周期**：
- `scope=slide`：离开该页 → `resolved`
- `scope=round`：本轮结束 → `resolved`
- `scope=lesson`：定稿前一直 `active`
- 新指令与旧指令冲突（同为 `correct` 且指向同一目标）→ 旧指令 `superseded`

### 2.3 落到课件（让输入影响最终产物）

**纠正类介入 → RevisionPatch**

- `intervene()` 落完 user_event 后：若 `intent=correct`，调用 `RevisionEngine.generate_patches_from_directive()`，生成 `target_type=slide|speaker_note` 的补丁
- 补丁 `status=applied`（**当场生效于下一版课件**），复盘页/版本对比页可回滚
- `RevisionPatch` 新增字段 `source_intervention_ids: list[str]`，复盘页可点开溯源到教师原话
- **可回滚**：回滚复用现有补丁状态机（`applied` → `rejected` + 重建版本），教师一键撤销

**督导遵循度评价**

- `build_supervisor_observation_prompt` 的 schema 增加：
  ```json
  "directive_compliance": [{"directive_id": "...", "followed": true, "evidence": "..."}]
  ```
- 未遵循 → 额外产出一条 `category=alignment, severity>=minor` 的 observation
- 复盘页显示「本轮教师指令 N 条 · 已落实 M 条」

### 2.4 前端交互

**输入框增强**（`ClassroomGroupChat.tsx`）
- 输入框上方两个小选择器：意图（提问/纠正/要求）、范围（本页/本轮剩余/整节课）
- 默认：意图=提问，范围=本轮剩余
- 已发出的指令在聊天区显示徽标：`[纠正 · 本轮]` + 状态（生效中/已落实）

**复盘页新增指令面板**（`ClassroomWorkspace.tsx` ReviewView）
- 列出本轮所有指令、意图、范围、状态
- 每条可展开看「教师原话 → 督导是否认定遵循 → 关联的 RevisionPatch」

### 2.5 暂停门（修掉骗人的勾选框）

**「学生提问后暂停」真实现**
- 新增 `interventions.after_question` 在 classroom_v2 的读取点：`orchestrator` 在 `student_initiated_question` 产出学生问题后，若开启则 `pause`
- 教师看到暂停 → 可在聊天框输入（意图默认「要求」，范围默认「本页」）→ 继续
- 与现有 `intervene` 复用同一条链路

**「教学设计后暂停」重定义**
- classroom_v2 本来就在 PPT 生成后停在审阅门（`awaiting_review`）
- 勾选 = 保持停住等教师确认（现状）；不勾选 = 审阅门自动通过，直接进课堂演练
- 在 UI 文案上明确这个含义

## 4. 风险与边界

| 风险 | 处理 |
|---|---|
| 指令继承导致 prompt 无限膨胀 | 只注入 `status=active` 且最多 5 条；超出按时间倒序截断并在日志标注 |
| 纠正类补丁与督导补丁冲突 | 补丁都进同一 `revision-patches` 列表，由教师在审阅页仲裁 |
| 范围=整节课 的指令跨轮存活 | 定稿时统一 `resolved`；跨轮时在新轮 start 时重新载入 |
| 学生感知教师指令导致行为失真 | 学生 prompt 只传「教师对课堂形式的要求」（如「多提问」），不传具体内容纠正 |
| 兼容旧数据 | 新表可空；旧 run 无指令时行为与现在完全一致 |

## 6. 已确认的决策

1. **纠正类补丁默认 applied（当场生效于下一版），复盘页/版本对比页可回滚**——用户选定。
2. **意图三分类：提问 / 纠正 / 要求**——用户选定。督导只对「纠正」「要求」判定遵循度；「提问」不产生约束也不产生补丁。
3. **两个暂停门都做**——用户选定。
4. **本轮范围：决策 3 + 决策 1/2/4 一起做**——用户选定（见第 7 节排期）。
