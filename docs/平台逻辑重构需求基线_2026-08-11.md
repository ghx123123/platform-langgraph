# 平台逻辑重构需求基线

> 版本：R1  
> 日期：2026-08-11  
> 定位：教师优先的课程资料、教学设计与成果生产工作台

## 1. 重构目标

本轮重构优先解决“用户不知道当前对象、下一步和数据去向”的问题，而不是增加更多页面或功能。

量化目标：

1. 任一页面均能在 5 秒内回答：当前课程是什么、正在处理什么、下一步是什么。
2. 一个教师动作只有一个主入口；同类次级入口只展示摘要和跳转。
3. 课程、单元、备课任务、会话和成果的上下文匹配率必须为 100%。
4. 文件处理、生成和导出均展示真实阶段、状态、耗时、异常和恢复动作。
5. 从进入已有课程到启动一次新备课任务，主要页面跳转不超过 3 次。
6. 刷新、前进后退和直接打开链接后，当前工作上下文可恢复。

## 2. 明确不做

- 不建设学生先作答、两级提示、答案解析或学习过程记录。
- 不建设按分钟执行的课堂话术和活动脚本。
- 不采集学生作答，不生成班级误区统计。
- 不把复杂网络图作为主要操作界面；数据图必须提供线性文字视图。

## 3. 统一术语与对象

| 产品术语 | 唯一含义 | 当前实现映射 |
| --- | --- | --- |
| 课程资料库 | 某学期某课程的原始资料集合 | `CourseArchive` |
| 资料单元 | 课程中的章节或讲次范围 | `DataHubUnit` / chapter |
| 备课任务 | 一次已确认的讲次、材料、知识范围、课时和深度 | 新增持久化 `Preparation`，由现有 `PreparationPack` 迁移 |
| 生成运行 | 针对一个备课任务的一次或多轮智能体运行 | `WorkflowRun` |
| 教师定稿 | 教师可审核、可恢复版本的教学成果 | `TeacherDraft` / `CourseDesignRecord` 的交付视图 |
| 资料包 | 从多个来源自由组合的附件型成果 | `CompositionRecord` |
| 导出文件 | 由某个确定版本生成的 Word/PDF/交换文件 | 新增 `ExportArtifact` 记录 |

禁止在面向教师的界面中混用“课程设计、教学成果、成果编排、文件输出”来指代同一对象。

## 4. 目标信息架构

### 4.1 课程与资料

职责：课程选择、目录同步、全局检索、文件状态和原页预览。

- 合并当前 `/hub` 与 `/materials` 的资料管理能力。
- 默认只浏览和检查资料；“用于备课”进入备课任务，不在这里直接修改成果。
- 显示资料处理统计：总文件、已解析、仅索引、失败、待更新。
- 默认采用文件目录式渐进展示：左侧只负责学期/课程/单元定位，中部只展示当前路径的下一级文件夹或文件，右侧详情在教师打开文件后再出现。
- 课程单元直接作为资料“主目录”，原始文件、上传文件夹和教师自建文件夹必须位于同一棵目录树，不再增加“原始资料”虚拟根；历史系统分区目录应自动迁移并合并同名根目录。主目录只管理原始资料，不展示提取正文或下游生成内容。
- 平台目录必须支持新建子文件夹、重命名、移动和递归删除；文件支持重命名、单项/批量移动和单项/批量删除。删除平台托管副本与目录引用，不直接删除教师电脑上的外部索引源文件。
- 课程资料库根节点必须按资料库 ID 与目录数据一一对应，并提供独立删除入口。删除前展示关联资料、文件副本、教学设计、资料包和会话的影响范围，二次确认后由后端统一级联清理；不得删除教师电脑上的源目录。
- 教师可在当前指定目录上传单个文件或完整文件夹，文件夹上传保留相对层级；新建文件夹时必须实时显示创建后的完整位置，主目录及其子目录中的文件夹均提供明确删除入口。上传和后端目录扫描只登记元数据并保存原文件，不自动提取正文；进入资料单元并明确选定本次备课材料后，后续节点才按需提取。
- 路径连接必须明确区分“上传文件夹副本”和“索引后端可访问目录”；选择完成后可按需展开文件清单，失败原因必须显示在弹窗内。
- 切换单元不得保留不可见的跨单元选择；搜索、筛选、面包屑和空状态都必须提供明确清除或返回动作。

### 4.2 本次备课

职责：确认本次教学输入，形成唯一且可恢复的备课任务。

- 明确显示课程、单元、讲次、主材料、配套材料、知识点、课时、深度。
- 不再进入页面后隐式全选全部资料；推荐项与教师已确认项必须区分。
- 提交前显示固定摘要；修改知识范围后产生新任务或新版本。

### 4.3 生成与打磨

职责：展示智能体处理过程，支持教师介入和同范围多轮优化。

- 运行必须绑定一个备课任务和一个范围摘要。
- 同一任务多轮保持 `scope_hash` 不变；变更范围必须派生新任务。
- 展示当前处理者、当前任务、阶段、步骤、耗时、心跳、Token、警告和恢复动作。

### 4.4 定稿与交付

职责：从当前任务进入正确成果，完成审核、版本和导出。

- 教师定稿、结构化教案、自由资料包是同一成果中心下的明确类型，不是隐藏子页面。
- 从会话点击“编辑与导出”必须打开该会话关联的成果。
- 每种成果只有一个主 Word 操作；模板和交换格式为次级设置。

## 5. 数据处理可视化

默认采用 7 节点线性处理链，不使用装饰性流程图：

```text
原始文件 → 正文提取 → 章节结构 → 范围确认 → 智能体生成 → 教师定稿 → 导出文件
```

每个节点必须显示：

- `status`：未开始、处理中、已完成、需要复核、失败、已过期。
- `count`：输入/输出数量或字符、页面、内容块数量。
- `duration`：真实处理耗时。
- `message`：当前动作或结果摘要。
- `warning/error`：具体对象、错误码和原因。
- `action`：查看结果、重试、重新选择、继续下一步。
- `lineage`：输入版本和输出版本；详情页可展开来源列表。

后端统一演进为三个基础记录：`ArtifactVersion`、`ProcessRun`、`LineageEdge`。现有 `CourseDataReference` 作为血缘迁移基础。

## 6. 功能需求与验收

### P0：必须先完成

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| CTX-01 | 建立唯一备课上下文并写入 URL | A/B 两门课程各 2 个任务，刷新、前进后退、直接打开链接后课程/单元/任务/会话/成果匹配率 100% |
| CTX-02 | 阻止跨课程关联 | 前端只显示当前任务会话；后端对 archive/unit/design/run 不一致返回 409/422；至少 8 个错配测试 |
| NAV-01 | 成果入口语义正确 | 从会话点击“编辑与导出”连续 20 次均打开关联教师定稿或教案，不落到旧资料包 |
| CMP-01 | 消除编排初始化竞态 | 新建/追加目标必须明确；慢接口、刷新和快速跳转 20 组测试错误追加为 0 |
| PREP-01 | 消除隐式范围 | 启动前固定展示完整范围摘要；未经确认不得创建运行 |
| ITER-01 | 保证同范围多轮 | 同一任务所有轮次 `scope_hash` 一致；改范围必须派生任务 |
| DRAFT-01 | 防止编辑丢失 | 备课、编排和教案编辑在刷新/返回/切页 20 组测试中丢失字符数为 0 |
| DATA-01 | 持久化解析结果 | 单文件解析后刷新仍可恢复正文、分区、解析报告和原页定位 |
| LINK-01 | 显式设计-运行血缘 | 禁止按标题/章节猜测归属；每个生成内容块可追溯唯一设计版本和运行 |

### P1：完成主链后实施

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| ING-01 | 真实导入进度 | 逐文件显示解析、仅索引、失败、跳过原因和重试；49+ 文件时不把“仅索引”伪装成完成解析 |
| PACK-01 | 持久化备课任务 | 可重新打开；来源变化后显示过期；重复提交幂等 |
| RUN-01 | 运行重启恢复 | 后端重启后续跑或标记 interrupted；事件不重复，错误含 retryable 和错误码 |
| ART-01 | 统一成果时间线 | 教师稿、结构化教案、资料包共享版本/审核展示；导出可追溯唯一版本 |
| CMP-02 | 上游更新提示 | 编排块记录源版本；上游变化后显示差异，可保留快照或刷新 |
| EXP-01 | 导出历史 | 保存输入版本、模板版本、SHA-256、大小和状态；失败可重试 |
| DIFF-01 | 轮次差异 | 同页比较目标、重难点、教学环节和督导建议变化 |

### P2：持续优化

- URL 同步筛选、标签页、轮次和预览对象。
- 继续上次备课、复制上一讲次，目标 60 秒内启动。
- 任务级搜索、归档、最近使用，找回目标任务中位数低于 15 秒。
- 清理或隔离未挂载的旧版 teaching/debate/execution 和可视化组件。

## 7. 重复功能处置

| 重复能力 | 决策 |
| --- | --- |
| `/hub` 与 `/materials` 的导入、检索、预览 | 合并到“课程与资料”；备课选择作为任务步骤 |
| 三套来源预览抽屉 | 抽取共享 `PreviewDrawer`；深度文档预览保持独立 |
| 多处 ID 多选逻辑 | Hub/Composition 共用 `useIdSelection`；主材料规则保持领域独立 |
| 三套编辑器 | 不合并数据模型；统一成果入口、模式切换、状态和版本外壳 |
| 三套下载实现 | 合并下载、文件名、MIME、签名校验工具 |
| 多套提示条/复制反馈 | 合并 `InlineNotice` 和 `CopyAction` |
| 导航配置与路由映射 | 收敛为单一阶段配置，子页进入 URL |
| 未挂载旧版前端/后端 | 标记 legacy，确认无入口后分批删除，不与主链同时重写 |

## 9. 实施顺序

1. 修复成果路由和编排竞态，消除立即可见的错误入口。
2. 建立上下文校验，阻止设计与会话跨课程关联。
3. 持久化备课任务和单文件提取物。
4. 增加线性处理链与真实状态字段。
5. 统一成果外壳、版本与导出历史。
6. 建立 Playwright 主链，按本文件 ID 逐项放行。

每次只关闭一组验收 ID；未通过自动化和真实浏览器验证的需求不得标记完成。
