# Python 教材逐页结构修复实测（2026-08-10）

## 1. 材料与根因

材料：`book/python程序设计基础与应用(OCR)课本2.pdf`，9,325,591 字节，20 页。

逐页审计发现，每页都有覆盖率约 100% 的扫描图片；同时存在一层不可见的 SimSun OCR 文字轨迹，20 页文字轨迹均为 PyMuPDF `texttrace.type == 3`。这层旧 OCR 虽然让每页能提取 459–2,595 个字符，却包含大量 `Pyhon`、`字符申`、`逆辑`、数字和代码符号错位。

旧逻辑只判断“文字是否超过 30 字”。因此这类页面被误判为原生文字 PDF，既不启动 OCR，也无法知道文字层已经失真。`pdf-inspector` 同样把文件分类为 `text_based`，但逐页接口判定 20/20 页需要 OCR 且 Markdown 全空，证明只依赖 PDF 分类不足以保证内容完整。

## 2. 修复方案

- 检测“整页图片覆盖率 >= 90% + 不可见 OCR 文字轨迹 >= 90%”的页面，标记为 `hidden_ocr`。
- 忽略旧文字层，直接读取页面内的原始扫描图；RapidOCR v6 输出文本框、坐标和置信度。
- 按页面坐标恢复阅读顺序，并用文本框高度和编号标题规则恢复标题层级。
- 保留每页 `character_count`、`line_count`、`title_count`、OCR 平均置信度和来源类型。
- 给每个内容分区增加 `page_start/page_end`，前端目录显示页码，点击目录会跳转 PDF 对应原页。
- 编号标题不再硬编码为某一章，`2.1.1` 到 `2.3.8` 均按结构识别；`3.14, 1.3e5`、`12.345` 等数字结果不会成为标题。

真实 `/api/documents/parse` 上传结果：

- HTTP 耗时：`186.42s`，首次加载和 20 页密集代码/表格 OCR 共同造成；直接解析约 `139.09s`。
- 20 页均有非空识别结果，最少页约 336 字符。
- 旧错误词 `Pyhon`、`Pyhom`、`字符申`、`逆辑运算符` 均为 0。
- 识别到 `>>>` 代码提示符 177 处，`map()` 3 次、`reduce()` 5 次、`filter()` 3 次、`range()` 3 次。
- 章节命中包括：2.1.1 常量与变量、2.1.2 整数/实数/复数、2.1.3 字符串、2.1.4 容器对象、2.2.1–2.2.6、2.3.1–2.3.8、2.4 关键字、本章小结和本章习题。
- 原页预览 HTTP `200`，返回大小 `9,325,591` 字节，与原文件一致。

## 5. 残余风险

- 质量分数为 70（中等），约 12% 文本行仍被标记为疑似 OCR 噪声；教材扫描图中的低清符号、二维码、公式和个别代码字符不能仅凭 OCR 保证绝对正确。
- 图片中的表格目前按视觉阅读顺序线性化，`table_count` 仍为 0；教师可通过原页预览核对表格。后续如需真正恢复单元格结构，应隔离评测 MinerU 或 PaddleOCR PP-StructureV3。
- 20 页高分辨率教材 OCR 约需 2–3 分钟，前端已有阶段状态和耗时显示；后续可增加后台任务、模型预热和页面级缓存。
