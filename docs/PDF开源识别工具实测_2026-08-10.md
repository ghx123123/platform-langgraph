# PDF 开源识别工具实测（2026-08-10）

## 1. 结论

- `pdf-inspector 0.2.6` 适合做 PDF 类型判断和原生文字页的高速结构提取，但不执行 OCR，不能直接识别本项目的扫描教材。
- `book-to-skill 1.3.0` 是“书籍内容整理为 Agent Skill”的上层流程，不是 OCR 引擎；对测试教材未得到可用正文，不应接入文档解析主链路。
- `RapidOCR 3.9.1 + PP-OCRv6` 在指定教材上比原 CnOCR 更快且人工抽查明显更准，已作为平台首选 OCR；CnOCR 保留为自动回退。
- 原生 PDF 后续可考虑让 `pdf-inspector` 负责干净文字页、OCR 负责扫描/截图页，但必须按页合并，不能用单一引擎覆盖整份混合 PDF。
- 公式、复杂表格、多栏和图文关系若要继续提升，下一阶段优先在隔离进程评测 MinerU 或 PaddleOCR PP-StructureV3，不直接把重型模型塞入当前 Web 进程。

## 2. 测试材料与方法

扫描教材：`第10章深度学习与大语言模型（工业AI）(1).pdf`，39 页，5,867,390 字节，39 页均为图片页。

另选两份平台生成/申报材料作为原生或混合 PDF：

- 8 页原生教学报告，用 `pdftotext` 结果作文字一致性参照。
- 20 页申报支撑材料，其中 5 页包含截图型内容，用于检验混合页面覆盖。

指标包括页覆盖、输出字符、主题词命中、结构保留、人工抽查错字、运行时间，以及与 `pdftotext` 的字符二元组重合度。后者只能衡量与原生文字层的一致性，不等同于有人工标注真值的 CER/WER。

## 3. 扫描教材结果

| 方案 | 页覆盖 | 可用正文 | 耗时 | 完整度与准确性观察 |
| --- | ---: | ---: | ---: | --- |
| 原平台 PyMuPDF + CnOCR | 39/39 | 6,697 字符 | 37.41 s | 核心主题可识别；封面书名、英文副标题、作者有明显错字 |
| `pdf-inspector` | 39 页均判为需 OCR | 0 字符 | 0.0058 s | 扫描分类正确，置信度 0.95；明确不提供 OCR 正文 |
| `book-to-skill` text 模式 | 0/39 | 0 字符 | 快速失败 | `pdftotext`、pypdf、pdfminer 均无法从纯图片页取得正文 |
| `book-to-skill` technical 模式 | 39 页图像占位 | 无可用正文 | 超过 5 min | 仅得到约 686 个源字符，内容均为 `<!-- image -->`，0 章节、无目录 |
| RapidOCR v6 原始 OCR | 39/39 | 7,123 字符 | 24.77 s | 平均置信度 0.9808；只出现 4 行低于 0.6；封面人工抽查正确 |
| 优化后平台主链路 | 39/39 | 6,650 字符 | 25.10 s | 去除重复页码/边缘噪声并生成 45 个标题；核心主题词覆盖与旧版一致 |

优化后平台的有效主题命中：深度学习与大语言模型 4、动物视觉机理 3、卷积神经网络 31、胶囊网络 16、计算机视觉 13、浅层学习的局限性 2、卷积运算 11、ImageNet 1、AlexNet 1。`池化层` 和 `ResNet` 仍未精确命中，属于需继续人工复核的细节。

封面关键文本由旧版的多处乱码/错字改进为：

```text
Introduction of Artificial Intelligence
第10章
深度学习与大语言模型
工业人工智能导论
机械工业出版社，2025
王万良 姚信城 王静 编著
```

平台最终字符数比 RapidOCR 原始结果少 473，主要来自页码、重复边缘文字和格式化去重；与旧平台相比少 47 字符，但核心主题命中未下降。当前不能据此声称所有单字均更准，准确性判断来自封面和正文抽样，不是完整人工标注 CER。

`25.10 s` 是与旧基线相同方式测得的直接解析耗时。真实 HTTP 上传首次冷启动为 59.34 s，同一服务进程第二次为 45.66 s，说明 Web 服务中的模型初始化和运行开销仍需继续优化，不能把直接调用数据当作教师端等待时间。两次 API 均返回 39/39 OCR 页、6,650 字符和 `PyMuPDF + RapidOCR v6`，原页预览返回 200 且字节数与源文件一致。

## 4. 原生与混合 PDF 结果

| 材料 | 当前 PyMuPDF 链路 | `pdf-inspector` | 参照与判断 |
| --- | --- | --- | --- |
| 8 页原生报告 | 2,332 字符，0.595 s，18 标题，二元组重合度 0.825 | 2,185 字符，0.023 s，25 标题，重合度 0.876 | `pdf-inspector` 更快、结构更干净，正确保留 `__init__`；偶有空表格列 |
| 20 页混合材料 | 9,632 字符，21.841 s，OCR 补 5 页，重合度 0.884 | 7,384 字符，0.046 s，重合度 0.972 | `pdf-inspector` 原生文字更准，但漏掉截图页；当前混合链路整体更完整 |

因此不能把整份 PDF 一次性交给 `pdf-inspector`。合理方案是逐页判定：原生页采用结构化文字，低文字量/图片页采用 OCR，最后按原页顺序合并并保留页码映射。本轮不接入该混合逻辑，避免在没有更多复杂原生教材回归样本时改变现有表格和标题行为。

## 5. 同类项目筛选

以下能力来自 2026-08-10 获取的官方 README，尚未在本机全部完成同材料实测，不能与上表实测数值等同看待。

| 工具 | 适合解决的问题 | 当前项目判断 |
| --- | --- | --- |
| MinerU | 扫描件、多栏、公式转 LaTeX、表格转 HTML、跨页表格；新版管线使用 PP-OCRv6 | 能力最完整的下一阶段候选；模型和运行链路较重，采用自定义开源许可，应先隔离部署和审查许可 |
| PaddleOCR / PP-StructureV3 | OCR、版面、坐标、表格、公式到 Markdown/JSON | 技术方向匹配；本机 `paddleocr 3.6.0` 因 `torch\\lib\\shm.dll` 报 `WinError 127`，暂不进入主进程；其 PP-OCRv6 已通过 RapidOCR ONNX 路径稳定使用 |
| Docling | 版面、阅读顺序、表格、公式、图片分类和扫描 OCR，支持 Windows | 可作为结构化解析候选；`book-to-skill` 的 technical 模式明确关闭 Docling OCR，不能代表 Docling 完整能力 |
| Marker | 表格、公式、多栏、扫描件；CPU/GPU 模式 | 依赖 PyTorch 和 Surya VLM/服务，模型许可对较大商业主体有限制，不适合当前轻量本地默认安装 |
| OCRmyPDF | 用 Tesseract 给原 PDF 叠加可搜索文字层，支持纠偏和清理 | 适合归档和原页复制，不负责教学目录、表格语义和 Markdown 结构；可作为离线预处理工具 |
| OpenDataLoader PDF | 本地布局与混合 AI 模式，输出 Markdown/JSON/坐标 | 官方声称混合模式总体 0.907、表格 0.928；需要 Java 11+，混合服务尚未本机复测，不直接采用官方数值作为本项目结论 |
| PyMuPDF4LLM / PyMuPDF Layout | CPU 版面、表格、按需 OCR、Markdown/JSON | 与现有 PyMuPDF 接近，但会锁定升级到 PyMuPDF 1.28.2，且仓库标注 AGPL；建议在独立环境做许可和兼容评估 |

## 6. 已落地改动与验收标准

- 后端依赖新增 `rapidocr>=3.9.1,<4.0.0` 和 `onnxruntime>=1.20.0,<2.0.0`。
- PDF 扫描页和 Word 嵌入图片优先使用 RapidOCR v6，加载失败自动回退 CnOCR。
- RapidOCR 与 CnOCR 输出统一为“坐标、文字、置信度”，保留视觉阅读顺序并过滤极低置信度噪声。
- 解析质量报告显示实际 OCR 引擎，回退原因进入可见警告。
- 单元测试覆盖 RapidOCR 坐标排序、低置信度过滤和 CnOCR 回退。
- 浏览器真实上传后显示 12 个候选知识点、26/26 内容分区、39 页原稿和 6,650 个已处理字符；页面横向溢出为 0。
- 修复扫描封面把“第10章”和下一行标题拆开时课程名只取章节号的问题，现合并为“第10章 深度学习与大语言模型”。

后续引入任何重型解析器前，至少要满足：39/39 页覆盖；上述 13 个主题词总命中不下降；人工抽查封面及 10 个正文片段；公式/表格专项样本有可量化提升；单文件耗时、首次模型下载、内存峰值和失败回退均可接受。
