# Qwen-MM-Plugins 优化分析与实测（2026-08-10）

## 1. 上游项目结论

分析对象：[QwenLM/Qwen-MM-Plugins](https://github.com/QwenLM/Qwen-MM-Plugins)，核对基线为 `83decb6ab2d051ea9eef05760db2d7e9fed8afaf`（2026-08-09），Apache-2.0。

该项目不是新的 PDF 全文 OCR 引擎，而是“Skill + MCP 工具”形式的多模态能力层。与本平台材料处理最相关的是 `core` 能力：

- `visualize` 将 PDF 每页同时渲染为页面图像和文本层，并支持指定页范围、最大页数与分辨率预算。
- `read_image` 依据视觉模型的 32 像素 patch 网格动态缩放，使用 small / normal / large 三档视觉 token 预算。
- `vision_chat`、`ocr` 通过 OpenAI 兼容的 DashScope 接口接收 data URL 或文件输入。
- 大响应有字节上限，外部调用支持 dry-run，工具错误以结构化文本返回。
- PDF 渲染使用 `pypdfium2`；文字层仍依赖 PDF 自带文本，不会自动识别并替换劣质隐藏 OCR 层。

因此，Qwen-MM-Plugins 适合启发“按页视觉复核”，不适合直接替换本平台已经实测有效的 `PyMuPDF + RapidOCR v6` 全文主链。

## 2. 未直接安装整套插件的原因

- 上游主要面向 Codex、Claude Code 等 Agent Harness，不是 FastAPI 业务服务组件。
- 官方说明 Windows 原生环境尚未验证，推荐 WSL2；当前平台需要保持 Windows 一键启动。
- 整套 `core` 会引入 `uvx`、MCP、pypdfium2、Playwright、地理/三维等大量与教师备课无关的依赖。
- 全页交给外部视觉模型会增加费用、等待时间与幻觉风险，也会削弱本地 OCR 的确定性和可追溯性。

采用策略：借鉴协议与交互模式，在现有架构中原生实现最小、可回退的单页视觉增强。

## 3. 已落地优化

### 后端

- 新增 `POST /api/documents/{document_id}/visual-analysis`：复核 PDF、DOCX、PPTX 原页预览中的指定页。
- 新增 `GET /api/documents/{document_id}/visual-analyses`：读取已经保存的逐页视觉证据。
- 页面按 32 像素 patch 对齐，提供快速 / 标准 / 精细三档分辨率预算。
- 本地页面只以受控 JPEG data URL 发送，不发送本地路径，也不要求外部服务访问材料 URL。
- 复用当前模型设置中的 OpenAI 兼容 URL、模型、密钥和超时；本地演示模型下明确提示先切换视觉模型。
- 返回结构化的页面摘要、视觉要素、备课提示、OCR 修正、置信度、响应时间与警告。
- OCR 修正必须能在本地提取文本中定位；无法定位的模型修正会被丢弃，不能覆盖 RapidOCR 原文。
- OCR 对照文本被 HTML 转义并限制为 350 字，降低提示注入、跨页混淆和长上下文空响应。
- 空 JSON 或不可解析响应自动重试一次；两次失败则返回错误，不覆盖历史有效结果。
- 支持 `dry_run`，可先验证页码、图像尺寸和请求体积而不调用外部模型。
- 同一页重新复核采用原子覆盖文件，避免重复记录和半写入状态。

### 前端

- 原页预览增加“视觉复核本页”，只分析教师当前查看的页，不阻塞全文 OCR 上传。
- 提供快速 / 标准 / 精细清晰度选择。
- 等待时显示当前步骤与实时秒数，完成后显示模型、响应时间、置信度和自动重试警告。
- 视觉证据按“页面摘要、视觉要素、文字修正、备课提示”分区展示，可折叠、可复制。
- 视觉面板与原页同屏，教师可以直接对照模型描述和教材版式。
- 已复核证据在启动教学设计时自动加入教师补充上下文，但不会改写原文和章节偏移。
- 桌面和移动端都限制视觉面板高度，确保原页预览始终保留可视区域。

| 快速 | 448 × 608 | 272,384 | 56,704 bytes | 0.359s |
| 标准 | 864 × 1216 | 1,050,624 | 167,178 bytes | 0.182s |
| 精细 | 960 × 1344 | 1,290,240 | 196,441 bytes | 0.186s |

真实 `MiniMax-M3` 视觉调用结果：

- 首次有效调用：12.117s，3 个视觉要素、4 条备课提示、4 条原始修正候选，置信度 0.92。
- 发现并修复提示词被误列为 OCR 修正的问题。
- 发现 HTTP 200 空 JSON 会覆盖有效结果的问题，新增空结果重试与写入保护。
- 使用 350 字对照窗口复测：首次结构化响应为空后自动重试，总耗时 24.563s；返回 3 个视觉要素、5 条备课提示、1 条可定位 OCR 修正，置信度 0.92。
- 补充识别内容包括二维码、代码与注释双栏关系、`reduce()` 折叠过程，以及 PDF 页序与教材印刷页码的差异。

浏览器验收：

- 桌面 `1440 × 960`：无横向溢出，视觉面板展开后原页区域为 `868 × 240`。
- 移动端 `390 × 844`：文档和操作区无横向溢出，原页区域为 `390 × 271`。
- 等待态秒数、成功回显、自动重试警告、复制、折叠和历史结果加载均通过。

## 5. 验证结果

- 正式后端测试：`142 passed`，仅有 4 条既有 SQLite Python 3.12 弃用警告。
- 前端 `tsc + vite build`：通过。
- 扩展执行 `tests + backend/tests`：`153 passed / 5 failed`；5 个失败均来自既有 `backend/tests/test_report_api.py` 的旧版报表文件名、mock 调用和状态码断言，与本次文档视觉功能无关。
- 后端健康检查与两条新 OpenAPI 路由均通过。

## 6. 当前限制

- 视觉结果来自概率模型，必须与原页对照；平台将其标记为补充证据，不替代本地 OCR。
- 当前按教师主动选择的单页调用，未自动扫描整本材料，避免成本和长时间等待。
- 不同 OpenAI 兼容模型对 `image_url` 的支持不同；不支持时会返回明确错误并保留旧结果。
- DOCX/PPTX 首次视觉复核依赖现有 Office/LibreOffice 转 PDF 预览能力。
- 精细档受原始页面渲染分辨率约束，不无条件放大低清扫描图。

## 7. 后续可选方向

- 为多页复核增加后台任务队列、取消按钮和费用/视觉 token 估算。
- 对图表数值和公式增加二次规则校验，将“模型描述”与“可验证数值”分开显示。
